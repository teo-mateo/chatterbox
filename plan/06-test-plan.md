# 6. Test plan

## 6.1 Layers, and what each one can prove

| Layer | Runs in CI? | Proves | Cannot prove |
|---|---|---|---|
| **UT** unit | always, `cargo test --lib` | parsing, formatting, budgets, state machines, error mapping | that Ergo actually behaves as `02` recorded |
| **IT** integration vs **fake server** | always | the full loop: connect → negotiate → register → join → send → ack → wake line, including error paths and weird batches | server quirks we did not think to simulate |
| **LIVE** vs real Ergo | on dispatch/manual, never blocking a PR | that `02-protocol-contract.md` still describes reality, and that gap fill works against a real history store | nothing else, but this is the only layer that protects FR1.6/FR3.4 for real |
| **E2E** shell acceptance | manual/dispatch | issue #1's acceptance scenario end to end, with two listeners and a scripted human client | performance, load |

The fake server exists because CI must not depend on tiny2, and because it can be made to misbehave
on demand (never grant a capability, echo with no label, abort a batch mid-way, send `433`), which a
friendly real server will not do for you. It is a TLS server with a self-signed cert generated by
`rcgen` per test, so the pinning path is exercised rather than stubbed out.

## 6.4 The live harness and the probe pattern

`tests/live_ergo.rs` and `tests/e2e/*` talk to the real Ergo on tiny2. They are gated on
`CHATTERBOX_LIVE=1` plus `CHATTERBOX_SERVER_HOST`/`PORT`, so CI without network access skips them
with a visible `SKIP live: CHATTERBOX_LIVE not set` rather than silently passing.

The raw-probe pattern that produced `02-protocol-contract.md` is kept, because it is the only tool
that answers "what does the server really do?" without trusting chatterbox's own parser:

```bash
mkfifo /tmp/f
openssl s_client -connect $HOST:$PORT -quiet -no_ign_eof < /tmp/f > raw.txt 2>/dev/null &
exec 9>/tmp/f
S(){ printf '%s\r\n' "$1" >&9; }
S "CAP LS 302"; sleep 2
S "CAP REQ :server-time message-tags batch draft/multiline draft/chathistory echo-message labeled-response"
S "NICK cbprobe"; S "USER cbprobe 0 * :p"; S "CAP END"; sleep 3
S "JOIN #cbtest$(date +%s)"; sleep 1; S "MODE cbprobe +B"; sleep 1
S "BATCH +t1 draft/multiline #cbtest…"; S "@batch=t1 PRIVMSG #cbtest… :line one"; S "BATCH -t1"
exec 9>&-
```

Why FIFO rather than a scripted client: pacing is explicit, output is the unmodified byte stream, and
a bug in a client library cannot hide a server behaviour. It lives in `tests/live/probe.sh` with the
`sleep` values as the documented lesson (a `CAP REQ` issued before the `CAP LS` pages have been
consumed is what produced the misleading `410` during planning).

## 6.5 Live/E2E etiquette (this server is shared with a human)

1. Nicks are prefixed `cblive<runid>` / `cbprobe<runid>`; channels are `#cbtest<runid>`; run id is
   `date +%s`-based, so parallel runs do not collide.
2. `trap '… PART …; QUIT …' EXIT` — teardown runs on failure too; no channel or process is left
   behind, and unregistered channels disappear on PART (`02#2.11`).
3. Announce once, in the test channel, not in `#hof`. `#hof` gets exactly one line per live test
   run, and only if the test needs the shared channel (E2E-2/E2E-5 do).
4. Never send a message over 100 lines, and stay under ~120 lines per channel per run — 100 is the
   measured `max-lines` (`02#2.6`); the rest is good manners.
5. Rate: no more than ~4 messages/s; Ergo's fakelag will delay us and the test would then fail for
   the wrong reason.
6. Credentials: none. The live tests must work without an oper account, an account registration, or
   a NickServ password. `KILL`-based tests are therefore forbidden; connection drops come from the
   relay in `tests/e2e/proxy.py` instead.

real socket teardown and a real gap without needing server operator rights.

## 6.7 CI

```
pull request / push to main:
  fmt --check → clippy --all-targets -- -D warnings → cargo test (UT + IT, fake server)
  → cargo deny check → cargo audit → musl release build → chatterbox --version smoke
workflow_dispatch + schedule (nightly, on a **self-hosted LAN runner**):
  live tests against tiny2 + acceptance.sh + the raw probes in 6.4, recording results to the issue tracker
build (all targets, no smoke): x86_64/aarch64-unknown-linux-musl + aarch64/x86_64-apple-darwin
```

Two things revision 1 got wrong here. First, `192.168.0.204` is RFC1918: a hosted runner cannot reach
it, so a live job without a self-hosted runner is a job that never runs and a green tick that means
nothing. Second, the probe was advisory. It is now a **gate**: `v0.1.0` cannot be tagged while the
nightly probe is red, because every protocol claim in `02` — and therefore FR1.6, FR3.4, FR5.3,
FR6.3 — rests on it (`07#R12`). macOS targets are built and never smoked, and the release notes say
so (`07#R19`).

Design choices worth keeping: the live job is dispatchable rather than required, because tiny2 is a
home server and a laptop off the VPN must not turn CI red; the nightly raw-probe job re-runs `02`
measurements and opens an issue when a measured fact stops being true — that is how the protocol
contract stays a contract; and `cargo test` gets `-Z random` ordering locally so tests never learn to
depend on order.

Determinism rules: no test sleeps longer than 500 ms except the live/E2E ones; the fake server uses
monotonic injected time so backoff tests run in milliseconds; every test that opens a socket uses
port 0; no test writes outside `tempfile::tempdir()`.
